## Long-term Knowledge

### Architecture

<!-- lore:01a0121f-585b-79e0-842a-b67bea967026 -->
* **rollouts-plugin-trafficrouter-gcloud release pipeline (tag-triggered)**: Release flow: workflow \`.github/workflows/release.yaml\` triggers via \`on: push: tags: - "v\*"\` (any tag matching v\*, e.g. v0.1.0) → runs tests, then \`make release-binaries VERSION=\<tag>\` cross-compiles darwin/linux amd64+arm64 binaries plus \`checksums.txt\`, then publishes a GitHub Release via \`softprops/action-gh-release@v2\` (auto-generated notes, no CHANGELOG.md) with binaries attached, \`contents: write\` permission. Makefile derives \`VERSION\` from \`git describe\` (overridable) and injects it via \`-ldflags\` into \`pkg/version.Version\` (also blanks \`VersionPrerelease\`). Separate \`.github/workflows/ci.yaml\` runs on PRs/pushes to main: gofmt check, \`go mod tidy\` drift check, \`go vet\`, \`go test -race\`, \`go build\`, using \`go-version-file: go.mod\` with build caching. README has a 'Releasing' section documenting \`git tag -a vX.Y.Z && git push origin vX.Y.Z\`.

<!-- lore:01a0119f-010e-71c7-b596-4095bc9bc330 -->
* **rollouts-plugin-trafficrouter-gcloud: SetWeight matches NEGs via HasSuffix, ConfigKey sentry.io/gcloud**: Argo Rollouts TrafficRouterPlugin for GCP backend services. ConfigKey is \`sentry.io/gcloud\`. Config fields renamed: \`CanaryNegPattern\`/\`StableNegPattern\` (was CanaryBackendName/StableBackendName), plus new \`UpdateStableCapacityScaler bool\` (JSON \`updateStableCapacityScaler\`). Backend matching changed from exact trailing-name match to \`strings.HasSuffix(backend.Group, pattern)\` via \`updateBackendService\` (no return value, no not-found/zero-match error — replaced the old \`setBackendCapacityScalers\` that counted matches and errored on zero). canaryScaler = \`float64(desiredWeight) / 100\` (must be float division — integer division silently truncates to 0 for all weights 1-99). Stable scaler defaults to 1.0; only computed as \`1.0 - canaryScaler\` when \`UpdateStableCapacityScaler\` is true. Old \`weightToCapacityScaler\`/\`maxArgoWeight\` helpers removed in favor of inline math. \`getPluginConfig\` no longer nil-checks the strategy chain. Re-reads backend service from GCP every call (no caching), per Argo Rollouts plugin RPC caveats.

### Decision

<!-- lore:01a0119f-0113-7ea4-a131-353015f4674b -->
* **gcloud plugin: backendServiceClient interface for testability**: Chose to abstract GCP backend-service calls behind a \`backendServiceClient\` interface (pkg/plugin/client.go) with a real implementation (google.golang.org/api/compute/v1, ADC auth, handles both global and regional backend services) and a fake/mock implementation injected in tests, rather than calling the GCP compute API directly inside SetWeight. Rejected calling GCP APIs directly because it would make unit tests require real GCP credentials/network calls. This let plugin\_test.go table-test weight conversion, backend matching by group URL, zero/full weights, out-of-range weights, and missing-backend errors without touching real GCP infra.

### Gotcha

<!-- lore:01a0119f-0119-7a74-8264-ad63cd88714b -->
* **gcloud plugin: NEG matching via HasSuffix is silent on zero matches (regression)**: A single backend service can hold multiple regional backend entries per logical NEG name (confirmed in sentry-us2: \`snuba-api-0-http-backend-service-v2\` has several \`k8s-default-snuba-api-canary\` entries, one per region). Matching now uses \`strings.HasSuffix(backend.Group, pattern)\` against \`CanaryNegPattern\`/\`StableNegPattern\`, looping all \`svc.Backends\` in \`updateBackendService\`. BUT the earlier safety net (count matches, error if canary or stable count is 0) was removed in this refactor — a typo'd pattern or a NEG matching neither pattern is now silently left untouched with NO error. Trap: assuming the old error-on-zero-matches behavior still exists — it doesn't after the HasSuffix rewrite. If re-adding safety, restore a 'matched zero backends' guard (flagged but not yet implemented as of this session).

<!-- lore:01a01215-3f96-71ba-919d-a3cb85f62d6f -->
* **plugin.go canaryScaler: integer division truncates weight/100 to 0**: \`canaryScaler := float64(desiredWeight / 100)\` performs INTEGER division before the float64 cast, so canaryScaler is 0 for every Argo weight 1-99 and only 1 at weight=100 — looks correct because the surrounding types are float64, but the division itself happens in int arithmetic first. Fix: \`float64(desiredWeight) / 100\` (cast before dividing). Watch for this pattern anywhere capacity scalers or percentages are computed from int weights in this codebase.

<!-- lore:01a0121f-5860-7cbe-9ef8-3387b56ef121 -->
* **rollouts-plugin-trafficrouter-gcloud: go module path (argoproj-labs) != git remote (getsentry)**: The repo's git remote is \`git@github.com:getsentry/rollouts-plugin-trafficrouter-gcloud.git\`, but \`go.mod\` still declares module \`github.com/argoproj-labs/rollouts-plugin-trafficrouter-gcloud\` — a fork that kept its original upstream import path. Decision: leave the Go module path unchanged (it's internally consistent for imports and low-risk to change), but any user-facing URL (release download links, install instructions, badges) MUST point to \`getsentry\`, not \`argoproj-labs\`, or users get 404s. This was caught once already (README release URL was stale) — check for this mismatch whenever adding new docs/links/CI referencing the repo host.
